1. Fixed discovery reuses the bounded search/header/body/barrier scan (≤5 admitted candidate headers,≤12examined,2500steps/1s/4s main). It requires a separate exact observed group-public signal, one heading/readable body, complete co-located header and eligible link enumeration. Generic Public alone does not create an action.
2. Temporal label/visible text/semantic time proof is supported. For obfuscated timestamps, `UNIQUE_HEADER_PLACEHOLDER` requires exactly one eligible placeholder link in that same header, after excluding heading/author (`rel=author`, including ancestor), group-only links, body/comment/quote, media/heading-containing links, controls/menu/toolbar/form scopes, explicit popup attributes except false, disabled/download/new-window links and known actions. 3. Discovery binds actual node/root/header/public/body identities and original href inside isolated-world private state; no DOM marker/PII is written. Only the first unambiguous bound target can be opened. MutationObserver marks that boundary stale. CLICK consumes the binding, reruns the entire fixed guard scan, and checks the same nodes/document/raw search URL/href plus mutation state. Replacement with identical href or rewrapping the header fails closed. No skip/retry to another cached target.
4. Exactly one native HTMLElement click dispatches the observed element's handler. No loadURL placeholder, constructed post route, hover/scroll/See more or arbitrary selector/script/URL input. SPA target event may arrive before WebContents current URL updates; the controller waits for the corresponding actual main-route event/current exact URL under the same10s deadline. It allows only one post transition: SPA generation unchanged or one START+COMMIT/new generation. Raw-route swaps/redirect/extra navigation, owner loss/Stop and unsupported destination abort.
5. One existing fixed current-post read (≤4s main/1s script/2500steps/800chars). Qualifying persisted completion must match owned view, observed route and new read refs/hashes. Result `OPENED_POST_SAMPLE` means diagnostic click→route→read proof only. Candidate/permalink/source/hints remain UNVERIFIED; full_text_verified false. An absent/late/ambiguous/barrier read stays INCONCLUSIVE.
