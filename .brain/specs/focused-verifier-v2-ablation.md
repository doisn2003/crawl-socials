# Focused verifier v2 — isolated development proposal

This module is an experimental opt-in audit, not enabled by default in the production pipeline. An explicitly prepared active evaluation can use it through the durable VERIFY queue; no real campaign has been migrated. Its development input is the frozen deployed top20 on each platform (40 conversations), independently annotated by the core agent. These cases are development data after their errors informed this draft. Neither an improved score on these cases nor KEEP establishes production precision or reference truth.

User scope correction: CSD is a reusable multi-topic collection/filtering engine, not a project to manually curate a fixed café output. Case-specific revision and further ablation tuning were stopped. Keep the evaluated v2.0.0 prompt/version immutable as experimental history; its café-heavy examples are not evidence of generic semantic quality. No real campaign migration or label changes are authorized by this document. Cross-topic fixtures cover consumer-product advice, travel, education and cafés to verify intent/context serialization, comment-parent linkage, exact spans and temporal evidence validation. They use a fake model and therefore establish software contracts only. Production semantic claims require a separate cross-topic evaluation.

The audit retains substantive consumer reviews and useful guides without requiring a question, first-person wording, negative opinions, or comments. It checks specific contradictions: an explicitly bounded request that expired before the snapshot, employment-context questions, demonstrated provider promotion without a consumer opening, business-operator-only discussion, thin check-ins, and demonstrated mismatch with the campaign topic. Identity uncertainty is not a rejection rule. A consumer opening in comments can retain a promotional or expired root. Historical substantive reviews are not expired requests.

`src/application/opportunity-verifier-v2.ts` exposes `auditTentativeOpportunitiesV2(campaign, snapshots, proposals, gateway, options)` and immutable version/prompt/recipe hashes. It does not modify decisions or storage. Each audit returns KEEP, DOWNGRADE_NOT_YET, DOWNGRADE_UNRELATED, or UNRESOLVED, with exact evidence references and model invocation provenance. Expiry additionally needs an observed temporal quote, exact native publication timestamp, and a bounded end before `as_of`. Validation proves provenance and temporal consistency; semantic interpretation of the time phrase still requires the model and independent review.

`scripts/benchmark/focused-verifier-ablation-v2.mjs` defaults to `--mode plan`. Required inference inputs are `--export`, `--bundle`, `--campaign-directory`, and a new private `--output` directory. `--module-root .test-build/src` uses the tested module without a distribution build. Inference reads no reference file, checks frozen source bytes and deployed rank/context, and uses the original campaign gateway and its existing model ledgers. The campaign must be paused for its single writer contract.

`--mode infer` is an explicit operational action. It uses at most40 candidates, one attempt per model request, the original combined campaign budget (at most$3), and a default$0.06 cumulative usage upper bound for this verifier purpose. The leader authorized an explicit `--max-usd 0.12` extension after one request timed out with unknown usage; values above$0.12 are rejected. Failed, unknown and unfinished calls count against the allowance; rerunning does not reset it. No new model ledger or campaign is created for ablation. A model failure is unresolved, never a negative content label.

`--resume-from <previous ablation directory>` checks the same frozen source, campaign, input, version, prompt hash and original ledger directory. It retains completed audits exactly and submits only technical failures. Semantic UNRESOLVED cases are not silently retried. A new private output directory stores all40 merged audits and hashes linking the previous artifacts. `--batch-size 4` can reduce the size of the remaining requests without changing the prompt. A changed prompt/version cannot resume an old run; assess that revision separately.

Offline `--mode evaluate --audits <audits-private.jsonl> --reference <annotations-top20-core.jsonl> --output <report.json>` joins exact IDs/as-of only after inference, reports retained true positives, removed false positives, new false negatives and unresolved cases separately by platform. It cannot estimate recall over all collected roots. Use fresh unseen evidence for any subsequent release gate; do not silently retune using a supposedly untouched holdout.

Promotion to the product default requires checking false-positive cleanup alongside preservation of genuine reviews and comment openings across topics. The implemented migration/backfill infrastructure stores original and audited decisions under an explicit composed filter recipe/context, preserves raw roots, and retains the same cost ledger. This document does not trigger a real migration or certify the experimental policy.
